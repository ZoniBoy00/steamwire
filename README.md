# steamwire

An async Rust library for talking to the Steam network, ported from
[SteamKit2](https://github.com/SteamRE/SteamKit) (.NET), with its tools.

It covers what SteamKit2 does, but not as a line-by-line copy: it has an
idiomatic tokio API, with one cloneable `SteamClient`, `async fn` requests
that resolve to their responses, and an `Events` stream for everything else.

```rust
use steamwire::{Config, SteamClient};

#[tokio::main]
async fn main() -> steamwire::Result<()> {
    let (client, mut events) = SteamClient::connect(Config::default()).await?;
    client.log_on_anonymous().await?;

    let info = client.pics_get_product_info(&[480.into()], &[]).await?;
    println!("{:?}", info.apps[&480].key_values["common"]["name"].as_str()); // Some("Spacewar")

    client.log_off()?;
    Ok(())
}
```

## Parity with SteamKit2

| SteamKit2 | steamwire | Notes |
|---|---|---|
| `CMClient`, `SteamClient` | `client` | jobs, multi-part replies, heartbeats, `Multi` unpacking |
| `TcpConnection`, `UdpConnection`, `WebSocketConnection`, `EnvelopeEncryptedConnection` | `net` | TCP and UDP share the encryption layer (`net/envelope.rs`) |
| `Discovery/*`, `SteamDirectory`, `ContentServerDirectoryService` | `discovery`, `webapi` | `netfilter` servers serve TCP and UDP, as in SteamKit2 |
| `SteamConfiguration` | `Config`, `WebApi::with_*` | protocol set, connection and job timeouts, HTTP client, Web API timeout |
| `DebugNetworkListener`, `NetHookNetworkListener` | `net::NetworkListener`, `NetHookListener` | same dump file names |
| `Authentication/*` | `handlers::auth` | QR, credentials + Steam Guard, token renewal |
| `IAuthenticator`, `UserConsoleAuthenticator`, `PollingWaitForResultAsync` | `auth::Authenticator`, `UserConsoleAuthenticator`, `CredentialsAuthSession::wait_with` | wrong codes are asked again |
| `HardwareUtils`, `IMachineInfoProvider` | `util::hardware`, `Config::machine_info_provider` | machine GUID, physical MACs and boot disk serial, as the Steam client reads them |
| `SteamUser` | `handlers::user` | anonymous and token logon, account info, wallet, … |
| `SteamApps` | `handlers::apps` | PICS, licenses, depot keys, tickets, betas, free licenses |
| `SteamFriends` | `handlers::friends` | friend/clan cache, persona, chat rooms, history, profile |
| `SteamMatchmaking` | `handlers::matchmaking` | lobby cache, create/join/leave, metadata, search filters |
| `SteamContent`, `CDN/*`, `DepotManifest`, `DepotChunk`, `ClientLancache` | `handlers::content`, `cdn` | manifests (protobuf + binary v4), chunks, Lancache, proxies |
| `SteamCloud`, `SteamScreenshots`, `SteamWorkshop`, `SteamUserStats`, `SteamNetworking` | `handlers::*` | |
| `SteamGameCoordinator`, `SteamGameServer`, `SteamMasterServer`, `SteamAuthTicket` | `handlers::*` | GC jobs, game server logon/status, server queries, auth session tickets |
| `SteamUnifiedMessages` | `handlers::unified` | `call_service("Service.Method#1", …)`, notifications |
| Generated service classes (`Base/Generated/SteamMsg*.cs`) | `services` | generated by `steamwire-protos/build.rs`; the same methods and call/notification split as SteamKit2 |
| `KeyValue`, `SteamID`, `GameID`, `GlobalID`, `JobID` | `types` | text and binary KeyValues |
| `LzmaDecoder`, LZMA SDK `Encoder`, `VZipUtil`, `VZipDeltaUtil`, `VZstdUtil`, `ZipUtil`, `Adler32` | `util` | pure Rust ports; `vzip_compress` output is byte-identical to SteamKit2's |
| `Utils.GetOSType`, `NetHelpers` | `util::os`, `util::net` | OS type from the running system, private IP obfuscation |

| NetHookAnalyzer2 | `steamwire-tools nethook` | a CLI tree view instead of the WinForms GUI |
| ProtobufDumper | `steamwire-tools dump-protos` | custom options included; output recompiles with protoc |
| NetHook2 | `steamwire-nethook` | Windows DLL, adapted from steamkit-rs (see below) |
| SteamLanguageParser | `crates/steamwire/build.rs` | generates the enums and `Msg*` structs at build time |
| ProtobufGen | `steamwire-protos` (prost-build) | |
| `SteamKit2.GC.{CSGO,Dota,TF2,Deadlock}.Internal`, `SteamKit2.WebUI.Internal` | `steamwire-protos` features `csgo`, `dota2`, `tf2`, `deadlock`, `webui` | `protos::csgo` etc., from SteamTracking/Protobufs at the commit SteamKit2 pins |
| (SteamHelper-rs CS2 client) | `steamwire-cs2` | inspect links, item details, profiles, matches, the CS2 inventory; over `SteamClient::subscribe_gc` |

## Layout

```
crates/
  steamwire-protos/     prost types and descriptor sets from proto/ (vendored protoc)
  steamwire/
    steamd/             SteamKit2 SteamLanguage files, compiled by build.rs
    src/
      client/           SteamClient, Config, events, jobs
      net/              WebSocket, TCP, UDP, channel encryption, debug listener
      discovery/        CM server list and providers
      messages/         headers, Packet, ProtoMsg, ClientMsg, GC messages
      handlers/         one module per SteamKit2 handler
      cdn/              CDN client, depot manifests, chunks
      types/            SteamId, GameId, GlobalId, JobId, KeyValues
      util/             LZMA, VZip/VZstd/zip, crypto, IP helpers, machine ID
      webapi/           Web API client and CM directory
    examples/           anonymous, bot, cdn_download, depot_download, handlers_tour, live_checks, account_checks,
                        account_changes, machine_info, qr_login, service_call, webapi
    benches/            criterion benchmarks of the codecs
    tests/              CDN fixtures (tests/data/cdn), PICS captures (tests/data/pics),
                        SteamKit2 VZip output (tests/data/vzip), parser robustness tests
  steamwire-community/  web side: web session, trade offers, inventories, confirmations,
                        authenticator add/remove, wallet purchases (example: community_checks)
  steamwire-cs2/        CS2's game coordinator: inspect links, item details, profiles, matches,
                        the CS2 inventory (example: cs2_checks)
  steamwire-tools/      NetHook analyzer and protobuf dumper (library + CLI)
  steamwire-nethook/    NetHook2 DLL (Windows only)
fuzz/                   cargo-fuzz targets (not in the workspace)
```

## Examples

```sh
cargo run -p steamwire --example anonymous                 # logon + PICS over WebSocket
cargo run -p steamwire --example anonymous -- tcp          # over encrypted TCP
cargo run -p steamwire --example anonymous -- udp          # over encrypted UDP
NETHOOK=1 cargo run -p steamwire --example anonymous       # also dump every message
cargo run -p steamwire --example cdn_download              # Spacewar's manifest and files from the CDN
cargo run --release -p steamwire --example depot_download  # a whole depot, updated in place on later runs
cargo run -p steamwire --example bot                       # chat bot that reconnects; --token-file keeps the logon
cargo run -p steamwire --example machine_info              # what the machine ID is made of here
cargo run -p steamwire --example handlers_tour             # a call to each handler
cargo run -p steamwire --example live_checks               # anonymous + game server checks, options
cargo run -p steamwire --example account_checks            # checks that need your account (QR login)
cargo run -p steamwire --example account_checks -- --credentials --code --write   # password, Steam Guard code, changes
cargo run -p steamwire --example account_changes           # changes between two of your accounts
cargo run -p steamwire --example account_changes -- --refriend   # also remove and re-add the friend
cargo run -p steamwire --example service_call              # unified messages + heartbeat soak
cargo run -p steamwire --example qr_login                  # log on to your account with the mobile app
cargo run -p steamwire --example webapi                    # Web API as JSON, KeyValues and protobuf
```

Set `RUST_LOG=steamwire=trace` to see every message sent and received.

## Tools

```sh
# List or decode a NetHook dump (from NetHook2 or NetHookListener).
cargo run -p steamwire-tools -- nethook path/to/dump
cargo run -p steamwire-tools -- nethook path/to/dump --emsg ClientLogOnResponse

# Recover the .proto files compiled into a binary.
cargo run -p steamwire-tools -- dump-protos "C:/Program Files (x86)/Steam/steamclient64.dll" -o protos
```

`steamwire-nethook` builds `steamwire_nethook.dll`, which is injected into a
running Steam client with `rundll32 steamwire_nethook.dll,Inject` and writes
dumps that `steamwire-tools nethook` reads. It modifies the Steam client
process, so use it only on your own machine and account.

## Steam Guard

```rust
use steamwire::handlers::auth::{AuthSessionDetails, UserConsoleAuthenticator};

let mut session = client
    .begin_auth_session_via_credentials("user", "password", &AuthSessionDetails::default())
    .await?;
// Asks for the email or mobile code on the console (again if it's wrong),
// or waits for the confirmation in the app.
let tokens = session.wait_with(&mut UserConsoleAuthenticator).await?;
```

With the authenticator's `shared_secret`, `SharedSecretAuthenticator`
generates the codes instead. `Config::machine_info_provider` decides the
machine ID sent at logon; by default it's read from the hardware like the
Steam client does, so Steam sees the same device every time.

## Unified services

Each service in the protobufs has a typed client in `steamwire::services`,
like SteamKit2's generated service classes. Methods that return
`NoResponse` are sent as notifications, and incoming notifications decode
with the service's `…Notification` enum:

```rust
use steamwire::protos::steam::CPlayerGetGameBadgeLevelsRequest;
use steamwire::handlers::unified::ServiceNotification;
use steamwire::services::{FriendMessagesClientNotification, Player};

let levels = Player::new(&client)
    .get_game_badge_levels(CPlayerGetGameBadgeLevelsRequest { appid: Some(440) })
    .await?;

// Notifications arrive as `Event::Message` packets (`EMsg::ServiceMethod`):
let notification = ServiceNotification::from_packet(&packet).unwrap();
if let Some(Ok(FriendMessagesClientNotification::IncomingMessage(message))) =
    FriendMessagesClientNotification::decode(&notification.method, &notification.packet.body)
{
    println!("{}", message.message());
}
```

## Lower level use

Any message can be sent with the generated protobufs:

```rust
use steamwire::{EMsg, ProtoMsg};
use steamwire::protos::steam::CMsgClientGamesPlayed;

client.send(ProtoMsg::new(EMsg::ClientGamesPlayed, CMsgClientGamesPlayed::default()))?;

// A request answered with a job reply:
let reply = client.call(ProtoMsg::new(EMsg::ClientPICSAccessTokenRequest, request)).await?;

// Unhandled messages and notifications arrive as events:
while let Some(steamwire::Event::Message(packet)) = events.recv().await {
    println!("{:?}", packet.emsg);
}
```

## Web side: steamwire-community

Steam's websites (steamcommunity.com, the store, the checkout) and the
`IEconService`/`IAccountCartService` Web APIs, which SteamKit2 doesn't
cover, are in the separate `steamwire-community` crate:

- `WebSession::from_client(&client, refresh_token)`: the `steamLoginSecure`
  and `sessionid` cookies and the access token, renewed through the client
  about an hour before the token expires.
- `TradeOffers`: list (all pages), get, send, accept, decline and cancel
  offers; `TradeLink`, the account's own trade link, trade hold durations
  and the trade protection acknowledgement. `Inventories`: anyone's public
  inventory, page by page, with item descriptions.
- `Confirmations`: list, accept and cancel mobile confirmations with the
  authenticator's `identity_secret` (from an `.maFile`).
- `authenticator::{add, finalize, remove, status}`: the Steam Guard mobile
  authenticator over the client connection (`TwoFactor.*`), saved as Steam
  Desktop Authenticator's `.maFile`. Save it before finalizing: it holds the
  revocation code.
- `Store`: the account cart (add, remove, clear) and buying it with the
  Steam Wallet only. `quote()` prices it without charging; `finalize(quote,
  max_total_cents)` pays, never retries, and refuses (cancelling the
  transaction) if the wallet can't pay all of it or the total is over the
  limit. Free games need no checkout: `request_free_license`.

All of it is tested offline against a local server. Trading, purchases and
the authenticator change the account, so they haven't been run live;
`cargo run -p steamwire-community --example community_checks` makes read-only
live checks.

## CS2: steamwire-cs2

The CS2 game coordinator client, ported from SteamHelper-rs, is in the
separate `steamwire-cs2` crate. `Cs2::connect(&client)` plays CS2 on the
logged-on account and greets the game coordinator until it welcomes it;
then, one request at a time with a cooldown (the game coordinator drops
requests that come too fast):

- `inspect` / `inspect_str`: an item's details from its inspect link
  (def index, paint, pattern, float, stickers, keychains, StatTrak, name
  tag), or offline when the link embeds the item.
- `player_profile`, `request_matchmaking_stats`: ranks, wins, level,
  commendations, cooldowns.
- `match_info(&ShareCode)`, `recent_matches`, `live_matches`: rounds,
  scores, players, demo links and share codes.
- `inventory()`: the account's CS2 inventory, kept from the game
  coordinator's shared-object cache, with storage units; `next_event`
  tells what changed.

It takes CS2's GC messages through `SteamClient::subscribe_gc(730)`, so the
client's `Events` keep everything else. Tested offline against a fake game
coordinator; `cargo run -p steamwire-cs2 --example cs2_checks` makes
read-only live checks (the account shows as in CS2 while it runs).

## Features

- `native-tls` (default): TLS for WebSocket, the Web API and the CDN from
  the system (SChannel, Secure Transport, OpenSSL on Linux).
- `rustls`: rustls with the platform's certificate store instead, so no
  system TLS library is needed (static and musl builds):
  `steamwire = { version = "0.1", default-features = false, features = ["rustls"] }`.

Without either, TCP and UDP connections still work, but WebSocket and HTTPS
don't.

## Building and testing

```sh
cargo build
cargo test --workspace                                   # no network needed
cargo bench -p steamwire --bench codecs                  # chunk, VZip, KeyValues, encryption throughput
STEAMWIRE_ROUNDS=100000 cargo test -p steamwire --test robustness   # a longer parser search
cargo +nightly fuzz run packet                           # in fuzz/: packet, key_values, manifest, compression
```

Requires Rust 1.89+. `protoc` is vendored, so nothing else is needed. On Linux,
the default TLS uses OpenSSL (`libssl-dev`, `pkg-config`). `steamwire-nethook` is
empty on non-Windows targets. CI runs the tests on Windows, Linux and macOS,
clippy, docs, the MSRV build, the 16 MiB VZip comparison and each fuzz
target for a minute.

The crate denies unsafe code; the only exception is the Windows machine ID
queries in `util/hardware.rs` (registry, adapters, disk serial).

Received data is shared, not copied: packets, `Multi` sub-messages and CDN
bodies are `Bytes` slices of the buffer they arrived in, and channel
encryption keys its AES and HMAC state once per connection. The LZMA
decoder and encoder run in debug builds too, but for large depots build with
`--release`.

## Versioning

Semantic versioning, with [CHANGELOG.md](CHANGELOG.md). Before 1.0 a minor
release may change the API. Types that Steam may extend (callbacks, events,
results, `Error`) are `#[non_exhaustive]`, so new fields and variants don't
break code that matches on them.

## Known differences

- The machine ID: on macOS there is no MAC (as in SteamKit2), and the disk
  ID comes from `diskutil info /` instead of DiskArbitration (that needs
  `unsafe` FFI, which the crate keeps to Windows). The Linux code path runs
  in CI (`machine_info` on Ubuntu) but hasn't been compared with
  SteamKit2's output; the macOS one is only compile-checked.
- The default logon `machine_name` and auth `device_friendly_name` end in
  " (steamwire)" where SteamKit2's end in " (SteamKit2)".
- `Interface::call_protobuf` takes only the request, no extra arguments.
- Verified against Steam: the anonymous and game server flows, CDN, Web API
  and NetHook (`live_checks`); with a real account QR and credentials
  login, Steam Guard (app confirmation, code with wrong-code retry, approval
  after a code), token logon and the read-only handler calls plus lobbies
  and persona state (`account_checks`); and between two accounts friend
  requests, removal, blocking, chat messages, persona names, lobby invites,
  joins and owner changes, plus creating leaderboards, free licenses and
  the TF2 game coordinator (`account_changes`), the rustls feature, and
  whole-depot downloads with updates (`depot_download`).
- Tested only offline: the legacy chat rooms (`join_chat`,
  `send_chat_room_message`, kick/ban; replaced by Steam's newer chat),
  `share_file` (needs a Steam Cloud file), `SharedSecretAuthenticator`
  (needs an authenticator's shared secret; checked with node-steam-totp's
  vectors) and the macOS code paths.
- `add_screenshot` sends the request as SteamKit2 does, but Steam answers
  `Fail` unless the image was first uploaded to UFS, which SteamKit2 doesn't
  implement either. `add_friend_by_name` gets `Fail` from Steam today.
- Not ported, by design: the `CallbackManager` (requests are `async fn`s
  and the rest arrives as events), C# operator overloads and implicit
  conversions, `IsolatedStorageServerListProvider` (.NET-only storage; use
  `FileServerListProvider`), `HttpClientPurpose` (one `reqwest::Client`,
  replaceable with `WebApi::with_http_client`), `DebugLog`/`ILogContext`
  (`tracing` instead) and `DateUtils` (`std::time`).
- Not in SteamKit2 but in `steamwire-community` (see above): trading,
  inventories, mobile confirmations, adding and removing the authenticator
  and store purchases; and in `steamwire-cs2`, CS2's game coordinator
  client (SteamKit2 has only the generic game coordinator handler). Not
  ported from SteamHelper-rs: its password web login (the CM auth sessions
  replace it). `steamwire-cs2` doesn't reconnect: SteamHelper-rs's client
  reconnects and greets again, but steamwire has no reconnecting client, so
  a disconnect ends the session (`Error::Closed`), and its subscription
  channel never drops messages (no `Lagged` from it).
